# ApexDental 微信小程序 MVP

患者、前台、医生和诊所管理员使用**同一个微信小程序**。小程序按登录身份显示患者页面或诊所工作台；`server` 负责身份、权限、预约号源和数据保存。根目录的 `index.html` 是早期浏览器视觉稿，不属于正式交付。

### 专属护理流程、今日任务与失访跟进（2026-10-03）

- 医生/管理员从已完成预约或就诊时间轴“安排多节点计划”进入，选择洁牙、拔牙、正畸或种植流程。选择会替换当前草稿节点，保存预览后统一发送。起始日期默认实际接诊完成日期（旧记录无事件时使用预约日期），可手动核对调整；流程日期与说明均可编辑，过期节点调整至今天。洁牙含当天、第 3/7/30 天及 180 天复查准备；拔牙含第 1/3/7 天；正畸含第 1/7/14/30 天；种植含第 1/3/7/14/30/180 天及医生护理与用药提示节点。说明只提示按接诊医生要求执行，具体护理、用药与正式复查安排由医生填写。
- 患者首页“今日任务”汇总今天到期护理、逾期未反馈、今天就诊与到期未预约复查，支持家庭成员筛选、刷新、错误重试及反馈/预约跳转。共享家人仅查看，不能代交反馈或预约。已反馈等待处理的护理在护理详情继续查看；今日护理完成率以今天应反馈的任务为分母，已处理才计完成。
- 每个新增节点可由医生启用“无异常反馈自动随访”（默认关闭）。仅患者选择无疼痛、无出血、无肿胀，且没有补充文字或照片时，系统在同一事务中保存反馈、自动处理意见与事件并完成当前节点；后续已发送节点继续按原日期提醒。其他反馈全部进入人工处理，照片仍由医生查看。旧单任务保持人工处理。自动处理意见与时间轴对患者可见。
- 护理节点可设置失访阈值、再次联系间隔（各 1–30 天，默认逾期 7 天、间隔 3 天）。超过阈值或连续 3 次无法联系标记失访；状态自动计算，任务仍有效、不计完成。诊所护理详情填写实际联系说明，选择已联系/无法联系/暂不反馈；服务端生成再次联系日期，日期到达前从当前待办暂缓，但可在全部跟踪、失访或逾期筛选中查看。补交反馈自动恢复。联系记录仅诊所授权医生/管理员可见，并写入内部时间轴；重复请求不重复追加。
- 复查沿用人工再次联系日期，并增加上述三种联系结果；建议日期逾期 7 天或连续 3 次无法联系标记失访，有有效复查预约后恢复。复查卡片按已预约日期（无预约时按建议日期）显示倒计时/已过天数，完成后停止倒计时。复查预约仍走实际号源与确认流程。
- 计划详情按节点汇总阶段照片，进入对应节点认证查看原图，显示阶段、应反馈日期、处理意见与进度。节点照片提交后的反馈仍需人工处理。计划完成率 = 已处理节点 / 全部节点；运营统计按应反馈日期与医生统计全部已发送护理任务，新增完成率、按服务完成率、自动完成数、护理及复查失访数；草稿/归档排除，失访保留在分母，无任务显示“—”。前台不接收护理统计。
- 新接口 `POST /v1/care-tasks/:id/followup`，字段 `outcome/note/requestKey`；计划节点支持 `phase/autoNormal/lossAfterDays/followupIntervalDays`；复查跟进增加选填 `outcome`（旧客户端默认已联系）。SQLite 自动补充复查结果字段，护理内部跟进沿用事件记录，档案删除/注销沿用已有事务清理。

### 健康档案资料请求（2026-10-02）

- 患者从“健康档案 → 就诊时间轴 → 申请更正或删除资料”选择类型，填写涉及范围、更正前后内容或删除原因（1–2000 字）。首页“健康档案资料请求”查看进度、诊所回复与历史，待受理时可填写原因撤回。仅记录所属管理账号可申请，家庭只读共享账号无此权限。
- 管理员从工作台首页“健康档案资料请求”查看全部申请，可按待受理、处理中、已完成筛选并分页。填写受理说明后进入处理中，核验申请人与资料范围；更正时加载并编辑当前小结，删除时确认完整清除本次医疗内容，填写处理说明后勾选执行确认。无法办理时填写具体原因、后续联系途径；如需保留资料，应说明保留范围、依据和期限，由责任方核实，不由程序生成。
- 流程为“待受理 → 处理中 → 已完成/未予办理”，或“待受理 → 已撤回”。每次操作保存人员、说明、时间与版本。患者可查看自己申请的完整处理记录；医生和前台不能访问或办理诊所申请队列。重复提交同一请求标识返回原申请，同记录同类型仅允许一份未结束申请；冲突后刷新并重新选择申请。
- **完成申请会实际执行更正或删除，并与处理审计写入同一事务。** 更正需提交当前小结版本及完整更正内容，新增版本保留旧版。删除仅允许已完成/已取消预约，清除小结所有版本、护理任务/计划/反馈/处理/照片/快照、复查安排/跟进、就诊归档照片、关联站内提醒及预约备注；保留预约基本信息/状态事件与申请审计。其他就诊和家庭共享关系保留，删除档案无法再读取、编辑或重新归档，并从档案检索/总览移除。此操作是在线数据库记录删除，不涉及备份清理或 SQLite 文件安全擦除；账号注销使用独立申请流程，申请说明与审计仍保留。
- 接口：`GET /v1/record-requests?scope=mine|clinic&status=&page=1`、`POST /v1/record-requests`（`appointmentId/kind/details/requestKey`）、`PATCH /v1/record-requests/:id`（`status/version/note`；完成还须 `confirmed: true`；更正还须 `correction: {version,findings,treatment,nextSteps,structured}`）。申请类型为 `correction/deletion`，列表每页 20 条；数据与追加式处理历史保存在 SQLite。
- 验证命令：`node server/tests/record-requests-api.cjs`、`node server/tests/record-requests-page.cjs`。隔离接口和页面逻辑检查覆盖身份权限、只读共享、校验、幂等、状态机、版本冲突、审计事务、分页、持久化、过期响应及事件绑定。微信开发者工具编译和真机界面验收尚待用户安排。

### 档案扩展与资料权利办理（2026-10-02）

- **牙位图**：患者总览可切换成人恒牙（32 位）、儿童乳牙（20 位）和混合牙列（52 位），按 FDI 编号点选查看关联治疗小结及局部照片。标记只表示有记录，不推断健康状态，也不把空白当作缺牙。
- **同角度照片对比**：医生归档时填写拍摄角度、日期与选填牙位，局部照片必须注明牙位。成员总览选择两张同一成员、相同角度及牙位的照片，实际认证下载后并排显示并同步缩放（1–3 倍）。未标注角度和护理反馈照片不自动加入配对；人工角度分类不代表图像已自动配准。
- **检查单/影像附件**：医生/管理员从单次就诊归档 PDF、JPEG、PNG 或带 DICM 标识的 DICOM 文件，可标注牙位。每次最多 30 份，单份不超过 10 MB。患者、有效共享家人及本人接诊医生可认证下载；PDF/图片预览，DICOM 可下载转存，未集成 DICOM 阅片器。单次档案删除同时移除附件及旧导出包。
- **健康问卷**：成员总览填写主诉、过敏、药物、既往健康情况、治疗异常反应、出血史、孕期及吸烟情况；支持不清楚/不便回答。仅成员管理账号编辑并明确确认提交，医生和共享家人只读。保存保留版本、人员与时间，并校验版本冲突；未成年人问卷须通过监护核验。
- **监护人核验**：成员资料可填出生日期，子女或未满 18 岁成员默认受保护。管理人提交身份/监护关系 PDF 或图片、申请人姓名关系电话及成员出生日期；管理员独立查看材料、确认身份和关系、填写依据后通过或拒绝，也可撤销。管理员不能审核本人材料。成年子女可通过材料确认成年；修改关系或出生日期不会自行解除既有保护，改变已核验出生日期会撤销核验及共享，资料变更后需重新核验。原账号仍可查看既有档案；保护成员的新增共享、问卷、更正/删除、访问/导出和注销须核验通过。撤销核验同步撤销当前共享及未使用邀请，并阻止资料包下载。此为诊所人工材料核验流程，未对接外部实名核验服务。
- **访问/导出请求**：管理人从成员档案提交访问或导出该成员全部可见资料的请求，管理员先受理再确认执行。完成会实际生成 ZIP（成员基础资料、结构化档案 JSON、问卷版本、核验结果元数据、归档/恢复照片和检查/影像原文件），不包含诊所内部沟通、其他成员记录或核验原始证件。资料包仅申请人认证下载，有效期 7 天、最大 64 MB，过期包在查询请求队列及服务启动时清理。超限须联系诊所分批办理；当前界面未实现分批导出。单次资料删除使该成员旧包失效，共享家人和管理员不能代下载患者包。
- **账号注销**：本人明确确认范围并申请，管理员实际执行；未结束预约、有效员工身份或未完成监护核验会阻止办理。注销与审计同一事务，清除在线医疗内容/附件/问卷/核验材料/资料包，撤销所有会话和共享（含他人授予该账号的共享），脱敏成员、预约及请求说明，保留脱敏业务与安全审计及原身份哈希用于禁止重新登录。备份清理和文件安全擦除仍未实现。
- **访问/下载日志**：记录认证用户的档案访问、私有文件下载、资料办理与变更操作，含角色、成员/就诊/资料标识、服务端结果及北京时间，不记录正文或授权码。本人查看自己操作及所管理成员日志，管理员分页查询诊所日志；共享家人不能查询其他成员的完整日志，医生/前台无诊所日志队列权限。当前记录服务端处理结果，尚未接入独立审计存储或设备端保存回执。
- **AI 记录与复核随模块二建设。** 问卷、小结和照片对比保留人工填写及查看流程。

## 本机体验

1. 安装 Node.js 24 或更新版本，在 PowerShell 中进入项目根目录，运行：

   ```powershell
   $env:APEX_DEMO_AUTH = '1'
   node server/index.js
   ```

2. 用微信开发者工具打开 `miniprogram` 目录并编译。开发者工具需关闭“校验合法域名”，以便连接本机 `http://127.0.0.1:8787`。顶部显示“本机服务 · 患者”表示已连接；可点击顶部标记重连。
3. 首次管理员打开患者首页的“诊所员工入口”，填写诊所在册姓名和 `server/data/bootstrap-code.txt` 中的一次性授权码。绑定后会出现诊所工作台。该文件在首次管理员绑定后删除。
4. 管理员在工作台生成员工授权码，选择“前台”“医生”或“管理员”。医生授权时还需选定医生身份。员工在自己的微信账号或独立的开发者工具演示身份中输入该码；授权码 24 小时有效且只能使用一次。管理员也可以在员工名单中停用离职员工，停用立即生效。
5. 管理员在“诊所工作台 → 医生排班与号源”选择医生、未来 30 天内的日期、起止时间和容量，保存后切回患者端预约。新日期默认没有开放号源，需先配置排班。
6. 医生完成接诊后，在“护理与反馈队列”填写护理草稿的说明和反馈日期并发送。患者从首页“诊后护理”进入任务，提交恢复反馈；医生或管理员查看反馈，填写处理意见后完成任务，患者可以看到该意见。
7. 患者进入首页“健康档案”，选择某次预约查看就诊时间轴；医生和管理员可从工作台预约卡片的“查看就诊时间轴”进入，查看本次预约、到店、接诊完成、护理发送、恢复反馈和处理意见，并跳转护理详情继续处理。
8. 医生或管理员进入已完成接诊的时间轴，点击“填写就诊小结”，填写检查结果、处置说明和后续安排。保存后患者可见；后续修改会新增版本，时间轴中保留旧版并标明当前版本。
9. 保存小结后点击“将后续安排设为复查”，设置建议日期和复查说明；默认带入小结的后续安排。患者从首页“复查安排”或原就诊时间轴选择时段、填写联系电话并提交复查预约。复查预约关联原就诊记录，到店、完成接诊及后续护理沿用现有流程。
10. 从“诊所工作台 → 诊所待办”集中处理事项。支持按预约与接诊、护理、逾期复查和需关注筛选，以及按就诊人、医生或事项搜索。可以直接确认预约、处理取消申请、标记到店、完成接诊，或进入小结、护理及复查跟进页面。
11. 医生或管理员在“诊所工作台 → 护理模板”创建常用说明，设置适用服务项目和反馈间隔。在护理任务编辑页选用模板，会带入标题、正文和反馈日期，调整后再发送；也可将已填写的护理内容另存为模板。
12. 在患者首页“家庭成员档案”添加本人或家人，填写姓名、关系和联系电话。预约时选择就诊成员即可带入资料；首页、预约、健康档案、护理和复查页可按成员筛选。已有未归属记录可在就诊时间轴中手动确认归属。
13. 管理员在排班页加载已保存的排班，点击“将已保存排班复制到多个日期”，选择目标医生、日期和复制方式。支持未来 7 天、与来源同星期或全部日期快捷选择；预览确认覆盖情况和预约冲突后，批量复制并开放号源。
14. 患者在“诊后护理 → 查看并反馈”拍照或从相册选择恢复照片，上传后可以放大查看或移除；照片与恢复反馈一并提交。医生和管理员从护理反馈详情查看，时间轴显示照片数量并可跳转到详情。
15. 档案管理人在“家庭成员档案 → 授权管理”生成一次性家庭授权码，复制后自行交给指定家人。家人用自己的微信账号进入“家庭成员档案 → 接受家人授权”，查看成员与范围、填写姓名或称呼并确认接受；之后可按该成员查看档案。管理人可在授权名单中撤销访问，也可撤销尚未接受的邀请。

排班按半小时划分，起止时间需为整点或半点，结束时间不生成号源。每时段容量为 1–10 人；本版按医生和日期整体替换一个连续出诊范围。关闭预约会保留已预约患者；容量不能低于已占用数量，已有预约的时段不能从范围中移除。保存使用版本校验，遇到其他管理员已修改的提示时，请重新加载后编辑。旧版预约对应的号源会在迁移时保留。

项目目前配置的是微信体验号 `touristappid`。本机演示登录使用当前开发者工具/设备生成的独立身份。配置正式小程序 AppID 与服务端环境变量 `APEX_WECHAT_APPID`、`APEX_WECHAT_SECRET` 后，服务端支持用 `wx.login` 的临时凭证换取微信身份；未配置时仅在显式设置 `APEX_DEMO_AUTH=1` 后开放本机演示登录。

## 预约确认沟通记录

前台或管理员从工作台预约列表、诊所待办点击“确认预约”，进入“预约详情与处理记录”，查看联系电话及患者备注，填写 1–500 字沟通说明后点击“保存说明并确认预约”。服务端从登录身份记录员工标识、姓名、角色、确认时间及当次日期时段，页面按北京时间展示。

确认说明、状态变更和处理事件在同一事务保存；使用预约版本校验，避免按旧时间确认或重复生成记录。改期后重新确认会新增记录，原说明、操作人和原时段保留；取消申请后的“保留预约”沿用原流程，不新增确认沟通记录。历史预约不补造沟通说明。

沟通说明作为诊所内部记录：前台和管理员可在预约详情查看，接诊医生和管理员可在诊所就诊时间轴查看；患者和共享家人继续查看预约状态，不返回内部沟通说明。既有就诊时间轴的医疗档案权限保持原规则。

隔离验证：`node server/tests/confirmations-api.cjs`、`node server/tests/confirmations-page.cjs`。微信开发者工具编译和实际设备操作尚待验证。

## 角色权限

科普入口：患者首页“口腔健康小课堂”可直接选择牙痛、牙龈出血、冷热敏感、牙龈肿胀、口臭或智齿不适，查看关联的已发布文章；列表可继续组合症状、分类与关键词筛选，详情仍可预约关联服务。管理员在“诊所工作台 → 科普分类与文章”编辑文章时选择多个相关症状，保存后按原流程发布。症状标签用于查找内容，不提供诊断；无匹配内容不表示无需就诊。原两条示例标题仍为草稿，需补充诊所审核后的正文及标签再发布。旧数据库启动时自动新增标签字段，保留原内容、状态及版本。

| 角色 | 可见数据与操作 |
|---|---|
| 患者 | 浏览、提交和查看自己的预约；取消或申请取消自己的预约；查看自己的护理任务、提交恢复反馈、查看处理意见 |
| 前台 | 查看诊所预约；确认、拒绝、标记到店、处理取消申请 |
| 医生 | 查看分配给自己的预约；完成接诊，记录本人接诊的就诊小结；发送本人患者的护理任务并处理反馈 |
| 管理员 | 维护诊所、医生与服务资料，配置医生排班和容量；处理诊所预约、就诊小结、护理任务和反馈；发放授权码并停用员工 |

服务端根据会话中的身份校验每次请求。员工入口是否显示仅用于界面引导，不能代替服务端权限校验。同一账号被授权为员工后，仍可切回患者视图查看自己的预约。

## 诊后护理与反馈

### 诊后多节点计划（2026-10-02）

- 医生或管理员从工作台已完成预约的“安排多节点计划”创建计划；“诊后多节点计划”入口集中查看草稿、进行中与已完成计划。医生仅管理本人患者，前台不能访问。患者从首页或诊后护理页查看已发送计划，可沿用家庭成员筛选；家庭授权仍为只读，撤销后不能继续读取。
- 每个计划关联一次已完成且已有患者账号的就诊，支持 1–20 个节点。人工填写每个节点的标题、护理说明与反馈日期，可上移、下移、移除，保存草稿后继续编辑。也可归入本次就诊尚未属于其他已发送计划的已发送任务，保留原任务 ID、反馈、照片和处理意见，不重复发送。
- 草稿仅诊所可见，预览核对后“确认并发送整个计划”一次性发布全部新增节点。保存使用版本校验；整批发布、节点关联与事件记录在同一 SQLite 事务内完成，失败完整回滚，发布重试不会重复生成任务。不同草稿同时选择已有任务时，以成功发布的计划为准，其余计划需调整后重试。
- 患者可一次查看全部已发送节点，再进入各节点的护理详情提交反馈和照片；医生进入相同节点处理反馈。计划实时汇总已处理 / 总节点、逾期未反馈及待处理且需关注数量，全部节点已处理时标为已完成。需关注沿用原反馈标记，不新增诊断或自动医疗判断。
- 新增节点继续进入护理列表、诊所待办、就诊时间轴、统计与到期提醒队列，分别按任务计数。节点顺序用于展示，日期用于提醒，不按前一节点完成自动触发下一节点。接诊完成原有护理草稿保留为独立任务，未自动合并。
- 已发送计划及节点内容作为发送时的安排保留，本阶段不提供发送后修改、撤回、暂停、删除或追加节点；需要额外护理可继续安排独立任务或新计划。未实现按治疗项目自动选模板、自动临床节点编排、阶段触发或定时分批发送。
- 接口：`GET/POST /v1/care-plans`、`GET/PUT /v1/care-plans/:id`、`POST /v1/care-plans/:id/publish`。读取使用 `scope=mine|clinic`；草稿包含 `appointmentId/title/nodes/requestKey`，更新及发送要求 `version`。节点使用 `title/instructions/dueDate`，归入已有任务使用 `taskId`。SQLite 保存计划草稿、节点关联和包含操作人、版本与内容快照的追加式操作记录。
- 验证：`node server/tests/care-plans-api.cjs`、`node server/tests/care-plans-page.cjs`。已通过隔离接口与页面逻辑检查，覆盖权限、只读共享及撤销、校验、草稿冲突、原子回滚、幂等发送、已有任务归组、实时进度、持久化和过期响应。微信开发者工具编译及真机界面验收尚未进行。

护理流程为“草稿 → 已发送／待反馈 → 待处理 → 已处理”。完成接诊仅生成草稿，医生填写护理说明并发送后，患者才能看到任务。同一次已完成的就诊可通过“安排护理”追加任务。反馈包含疼痛程度、是否出血、是否肿胀和补充说明；存在不适或补充说明时标记为需关注，最终由医生判断并填写患者可见的处理意见。

旧版未处理的随访任务迁为草稿，已完成任务保留为归档记录；未关联患者账号的旧预约不能发送护理任务。已发送护理任务在反馈日期触发提醒，消息流程及真实微信配置见下文“订阅提醒与消息兜底”。

## 当前边界

### 家庭授权共享

- 共享按具体成员授予只读权限，包括该成员已有及后续的预约、患者总览、统一时间轴、结构化治疗记录、护理说明、已提交反馈、复查记录、就诊归档及已提交恢复照片。不能编辑成员、创建或取消预约、提交反馈、上传照片、转授权或改变记录归属；这些操作仍由原档案管理人进行。
- 授权码为随机一次性代码，数据库仅存哈希，24 小时有效，接受后绑定当前登录账号。接受前展示成员和只读范围；接收人填写的姓名或称呼用于管理人识别名单，不代表已完成实名核验。
- 接收账号的成员列表标明“已授权查看”，不显示管理人的联系电话，不进入预约的可选成员列表。共享不复制或合并成员档案，不转移原账号的管理权。
- 管理人可撤销未使用邀请及已接受授权；撤销后服务端每次读取记录或照片都会重新判断权限，旧授权码不能重新启用已撤销授权，恢复共享需生成新邀请。已下载、查看或自行保存的内容无法远程收回。
- 未提交的照片及诊所内部复查跟进记录不在共享范围内，未归属到该成员的旧记录也不共享。既有诊所角色权限继续按服务端规则独立校验。
- 接受共享需要不同的微信账号；本机演示需使用独立演示身份，正式微信身份仍需配置真实 AppID。复制授权码由用户主动操作，程序不会自动向他人发送消息。

### 恢复照片

- 每次反馈可选传 0–3 张 JPEG 或 PNG 照片，单张最多 3 MB、最多 2500 万像素；服务端检查文件头、尺寸和上传长度。小程序默认选用压缩图片，超出限制时需压缩后重新选择。
- 仅任务所属患者账号可上传和移除未提交照片。照片随反馈提交后固定关联该任务，患者可查看；只有接诊医生和管理员可读取已提交照片，前台和其他患者不能访问，其他医生不能查看。
- 图片二进制与归属信息保存在本机 SQLite 数据库，不提供公开文件地址；每次读取都需有效会话及任务权限。小程序下载后通过临时文件展示，切换角色、重新登录或卸载页面时清理已下载的照片缓存。
- 未提交照片暂存 24 小时，返回任务可继续填写；上传或查询时清理过期暂存数据。提交反馈时原子关联所选照片并移除未选附件；已提交照片不提供修改或删除入口。正式上线还需配置存储容量、保留与删除策略。
- 带照片的反馈列为需关注，交由人员查看；系统不进行自动图像诊断。照片数量会记录在时间轴中，实际照片在护理详情查看。

### 批量排班

- 仅管理员可操作，一次复制到 1–30 个目标日期，范围为未来 30 天。目标可为同一医生或另一位医生，不能重复或包含来源医生的来源日期。
- 使用来源已保存的时段和各时段容量，保留分段时段及不同容量；上方未保存的表单修改不带入。可以复制并开放全部来源时段，或保留来源各时段的开放状态。
- 目标日期原有排班将被整体替换；已有预约的时段必须保留，各时段容量不得低于已占用数量。预览展示新增、覆盖、冲突和剩余号源；有冲突时需调整来源或目标后重新预览。
- 预览有效期为 10 分钟，并绑定操作管理员及来源、目标版本。提交时重新检查排班版本、有效日期和实际预约占用。整批采用一个事务，任何目标冲突都不会写入其他日期；重复提交同一已成功预览返回原结果。
- 复制记录保留来源、操作人、批次及前后排班。批量开放不生成预约，不改变既有预约记录。

### 家庭成员档案

- 每个成员使用独立标识，由创建账号管理，跨账号不能读取、修改或用于预约。成员包括姓名、关系、联系电话及选填出生日期；每个账号最多启用一份本人档案。家属可使用负责联系的家人手机号。
- 新版小程序预约需选择启用成员，服务端使用该成员姓名并保存成员归属。同名成员不会合并，预约重复校验按成员标识进行。护理、反馈和复查沿用就诊记录的成员归属，复查不能换成其他成员。
- 旧版记录保持未归属，不会按姓名或电话自动匹配。患者可手动确认将当前账号的某次就诊及完整复查链归入同一成员；护理和反馈随关联就诊归属。已归属到其他成员的关联记录不可重新分配，无账号归属的旧记录不能认领。
- 修改成员姓名或电话不会改写历史预约快照；停用不删除历史记录，仍可按该成员查看档案，创建新预约或复查前需先恢复启用。成员变更和记录归属保留操作记录。
- 家庭档案由原微信账号管理，可通过一次性邀请授权其他账号只读访问；尚不支持管理权转移。诊所工作台仍按员工角色和接诊医生限制可见记录。

### 护理模板

- 模板由诊所人员填写，不预置医疗护理建议。医生和管理员均可创建和选用启用的诊所共享模板；医生只能维护自己创建的模板，管理员可维护全部；患者和前台不能访问模板接口。
- 模板包含名称、任务标题、护理说明、适用项目（通用或现有服务项目）、反馈间隔（0–365 天）和启用状态。反馈日期按选用当天的北京时间计算，0 天表示当天；医生可在发送前调整日期与内容。
- 已有护理正文时，选用模板会先确认替换标题、正文和日期。发送仍需要医生主动操作；保存模板不会发送任务。从护理任务另存模板后，原任务填写内容仍保留。
- 模板修改会保留版本，保存采用版本校验。停用后不再出现在选用列表；发送时校验模板是否启用、版本是否最新、是否适用本次服务。遇到模板变更，可重新选用，或保留正文改为手动填写。
- 护理任务保存最终正文，并记录来源模板版本；模板后续修改、停用均不改变已发送任务。患者只看到医生最终发送的护理说明。

### 诊所待办

- 待办由服务端根据实时状态生成，患者不能访问。前台只查看预约待办；医生只查看本人接诊、护理与复查事项；管理员查看全部。已停用员工的请求仍由会话权限校验阻止。
- 需关注的护理反馈优先显示，然后按处理优先级及日期排列。列表包括预约待确认、取消申请、今日或已过期的待到店预约、已到店待接诊、已完成但缺少小结、护理草稿、待处理反馈、逾期未反馈及逾期未预约复查。未来待到店和未到反馈日期的等待事项不进入待办。
- 事项的“需关注”来自患者反馈标记，用于人员处理排序，不是临床紧急程度判断。操作处理成功后列表更新，无法加载时展示错误和重试入口。
- 联系电话取自对应预约，可由员工点击“电话联系”调用设备拨号功能。逾期复查可记录实际联系结果及明天至未来 30 天内的再次跟进日期；记录仅医生和管理员可见，并保留在原就诊时间轴。
- 保存复查跟进后，当前复查版本在再次跟进日期前暂不进入待办，到期后重新显示；这不会将患者的复查标记为完成。患者预约后退出逾期待办；修改复查安排形成新版本后，旧版跟进日期不影响新安排。该功能为打开或刷新小程序时计算，没有后台自动消息推送。

### 复查衔接

- 每次已完成且有就诊小结的接诊可安排一次复查，建议日期范围为今天至未来一年。医生仅能安排本人接诊患者，管理员可安排全部；未关联患者账号的旧记录不能发送。
- 患者复查预约沿用原就诊人、医生和服务项目，服务端校验归属并建立关联。一个复查安排只能有一个未取消的预约，重复提交和多人修改使用事务与版本校验处理。
- 复查安排不会预占号源。实际预约仍需选择未来 30 天内开放时段，并由诊所确认。建议日期超出开放范围时，可选择其他开放时段或联系诊所。
- 已提交的复查预约取消后，安排恢复为待预约；接诊完成后显示复查已完成。取消申请中仍保留原预约，不允许重复预约。存在未取消的预约时不能调整复查安排。
- 患者和医生可查看待预约、超过建议日期、已预约及已完成状态；原就诊和复查记录可以互相跳转。修改复查安排保留历史事件。小结文字后续修改不会自动覆盖已发送的复查安排。
- 当前提醒为小程序内展示，尚未接入微信订阅消息或后台定时推送。

### 健康档案

健康档案按预约关联过程记录，使用事件实际发生时间（北京时间），同一次接诊的多个护理任务会归入同一时间轴。患者可查看当前账号管理及有效家庭共享覆盖的记录；医生仅可查看本人接诊记录；前台不能访问健康档案。患者不可见护理草稿。预约日期只是计划时间，不作为实际接诊时间；旧记录缺少过程事件时不补造时间。就诊小结包含检查结果、处置说明、后续安排三个必填文本字段，分别最多 2000、2000、1500 字；仅在完成接诊后填写。保存会记录操作人和时间，版本校验避免多人编辑覆盖；出现版本冲突时需返回时间轴加载最新版后重新编辑。小结保存后可主动衔接复查，护理任务仍需医生填写并发送。现已补充结构化诊断、FDI 牙位、治疗项目和材料；支持 PDF 与 DICOM 检查/影像附件；电子签名仍待建设。

- 服务仅监听 `127.0.0.1`，演示身份、初始医生名单、初始服务项目和号源规则均为开发数据。请只使用虚构的就诊信息。
- 小程序未连接服务时不能提交预约；旧版保存在小程序本地的演示预约不会自动迁入服务端数据库。
- SQLite 数据保存在 `server/data/apex-demo.sqlite`，不纳入版本控制。首次运行会自动给原有预约表增加归属字段；此前创建的旧预约只有员工能看到，患者账号不会自动认领。
- 还未完成真实小程序 AppID 接入、正式员工资料核验、生产部署与隐私告知；目前不能用于真实患者接诊。开发用演示登录默认关闭，只有设置 `APEX_DEMO_AUTH=1` 才开放。

### 订阅提醒与消息兜底

- 患者首页“消息与订阅提醒”查看站内消息、标记已读、进入预约/护理/复查列表并主动申请微信订阅；管理员工作台“消息发送记录”查看发送状态、错误、每次发送尝试与人工重试记录，可按失败、兜底、结果未知、自动重试筛选。每页 20 条，支持加载更多。只向原预约管理账号提醒，家庭只读共享账号不接收该消息；消息接口按账号隔离，发送记录及人工重试仅管理员可用。
- 预约确认生成提醒；就诊前一天和临近两小时各提醒一次。服务每分钟扫描，实际窗口为就诊前 2–24 小时生成前一天提醒、0–2 小时生成临近提醒；停机后落入临近窗口时不补发前一天提醒。安装本功能前的历史确认不重放；未过期的预约和待反馈/待复查事项会继续生成到期提醒。
- 已发送且未反馈的护理任务，以及没有有效关联预约的复查安排，在到期日北京时间 09:00 后提醒一次；停机或此前未发送护理时，在恢复服务后 09:00–24:00 的扫描中补入。护理按任务与反馈日期、复查按安排版本去重，提醒有效期为入队后 7 天，不按每天重复轰炸；修改复查建议产生新版本后可生成新提醒。护理草稿、已提交反馈、已预约复查不再推送。
- 每条提醒先持久保存站内消息及发送状态，再尝试微信推送。没有真实配置、演示身份、未订阅或微信返回授权不足时保留站内消息并标明兜底原因。推送成功不代表已读；患者主动“标为已读”只影响站内阅读状态。改期、取消、到店/完成、已反馈、已预约复查或过期后，旧提醒标明失效，发送前会再次检查。站内列表保留历史正文，患者应以业务详情最新状态为准。
- 明确的临时微信错误及发送前获取凭证失败，采用指数间隔自动重试，最多 3 次发送尝试；永久错误停止自动重试。发送请求超时、响应无法确认或发送进程中断记为“结果未知”，避免自动重复发送。管理员核实后可手动重试，总尝试上限 5 次；重新申请订阅可恢复符合条件的授权不足消息。客户端订阅结果只作为发送意愿记录，实际是否允许发送由微信接口校验，不承诺一次授权能收到所有后续提醒。
- 队列、订阅结果、已读状态、失败原因和尝试历史保存在 SQLite，重启保留。当前由同一个 Node 服务执行扫描和发送，停机期间不会推送；恢复后补扫有效事项。生产环境仍需持续运行服务、真实身份、HTTPS 请求域名及微信验收；当前不含短信/电话自动发送、通知外部人员或提醒规则管理界面。

真实微信配置：先将 `miniprogram/project.config.json` 的 `appid` 改为诊所真实小程序 AppID，在微信后台选用已获准的订阅模板。复制 `server/wechat-templates.example.json` 为本机配置，逐项替换模板 ID 和模板真实字段名（示例字段不能直接视为诊所模板）。启动前设置：

$env:APEX_WECHAT_SECRET = '填写真实Secret'

### 诊所运营统计

- 入口：同一个小程序内“诊所工作台 → 诊所运营统计”。管理员查看全诊所并可筛选医生；医生仅可查看本人；前台只能查看预约与实际到店、完成、取消数量，服务端不返回护理和复查数据；患者无法访问。统计响应不含患者姓名、电话或临床文字。
- 支持今天、近 7 天、近 30 天和自定义日期，含起止两天，单次最多 90 天；全部采用北京时间。看板支持刷新、加载与错误提示，切换账号或患者/诊所入口清除统计数据，过期请求不会覆盖新筛选结果。
- 预约当前进度按计划预约日期筛选：总数含所有状态，到店数含已完成；到店进度分母为未取消预约，包含待确认、取消申请中与未来预约。这是截至当前的进度，不是最终到诊率。实际到店、完成接诊、取消按对应状态事件发生时间统计，缺少历史事件的旧记录不补算。
- 每日趋势并列显示计划预约数（含已取消）、实际到店数、实际完成数，使用同一刻度；支持查看医生与服务项目的计划预约数量分布。
- 护理进度按应反馈日期统计已发送且未归档的任务，提交率为截至当前已反馈任务 / 应反馈任务；展示逾期未反馈、待处理及其中需关注数量。期间发送、收到反馈与处理数量另按各自实际时间统计。多项护理任务分别计数。
- 复查进度按当前安排的建议日期统计，已预约含待确认及取消申请中，但不含已取消；接诊完成才计复查完成。已过建议日期且未预约算逾期，内部再次联系日期不改变该统计。调整复查日期会改变所在期间，不作为历史冻结报表。
- 无分母时比例显示“—”。当前没有收费、订单或支付记录，因此未计算营收、客单价与收款统计。接口为 `GET /v1/statistics?from=YYYY-MM-DD&to=YYYY-MM-DD&doctor=医生名`，医生参数可省略（医生角色自动限定本人）。本阶段没有执行测试或编译，使用验证由用户安排。

### 就诊记录检索

- 诊所入口：“诊所工作台 → 就诊记录检索”。管理员可检索全部，医生只能检索本人接诊记录，前台不能访问该检索接口及健康时间轴。患者在“健康档案”使用相同检索，可组合现有家庭成员筛选，只能看到本人提交及当前有效共享授权覆盖的记录。
- 按就诊人姓名（完整或部分文字）、计划预约日期起止范围、医生组合筛选。日期含起止两天，可只填一端或均不填；开始晚于结束会提示错误。姓名按预约记录中的姓名查询，修改成员资料不会重写旧预约；同名记录不自动合并，授权范围不因姓名相同扩大。
- 查询包括各预约状态及其后续就诊记录；按预约日期、时段、创建时间与记录 ID 倒序稳定排列。每页 20 条，可加载更多，显示匹配总数及是否已有就诊小结。排序与日期筛选均不代表实际接诊时间，实际事件仍在时间轴中展示。
- 修改检索条件清空旧结果，点击“查找记录”生效；可重置条件。打开时间轴后返回保留姓名、日期与医生条件，重新加载第一页；成员筛选保持不变。账号和端切换清空检索数据，过期请求不会覆盖新条件。检索结果为实时数据，分页期间若记录发生变化，重新查找可获得最新列表。
- `GET /v1/records` 参数：`scope=mine|clinic`、`name`、`from`、`to`、`doctor`、`member=all|unassigned|成员ID`、`page`。成员参数仅作用于患者范围；服务端以当前身份和授权校验可见范围，采用 SQL 参数绑定。列表不返回联系电话或小结正文，进入详情时再次校验权限。
- 本阶段未运行测试或编译，使用验证由用户安排。

### 预约改期

- 患者在“我的预约”点击“调整时间”，或在本人可管理的就诊时间轴调整；管理员及前台在预约卡片点击“改期与变更记录”，管理员也可在时间轴调整。医生在诊所身份下不可改期；员工以患者端管理自己的预约时沿用预约管理人权限。家人共享权限仍为只读。
- 仅“待确认”和“已预约”支持改期，已到店、已完成、已取消及取消申请中的预约不开放。新时间需为明天至未来 30 天内原医生的开放半小时时段；必须不同于原时间，并填写 2–500 字原因。原日期已过期也可调整至有效新日期。
- 沿用原预约 ID、成员、医生、服务及复查关联，只调整时间并重新进入“待确认”。成功后原时段释放、新时段占用，待办列表进入确认队列；前台和管理员代为改期也需要随后重新确认。当前为直接改期后待确认，未另建审批或改期申请队列。
- 保存使用 SQLite 事务核验容量、同一成员同时段重复预约及预约版本。目标满员或关闭、日期无效、多人操作版本冲突时回滚并保留原预约。重复相同请求标识只返回原操作结果及当前预约状态；同一标识不能提交不同内容。提交超时可以重试，重新加载会清空未保存内容。
- 每次改期记录原日期/时段/状态、新日期/时段、原因、操作身份和实际操作时间，历史只追加，在改期页和就诊时间轴查看。患者本人、共享家人及原医生可在其授权时间轴中查看变更；前台仅能在改期页查看变更，不开放医疗小结。原因会向上述授权查看者展示。
- 复查预约改期保留原关联，原就诊时间轴的“提交复查预约”保留首次提交时的时间；新的改期过程在关联复查预约的时间轴中展示。日期统计和检索使用当前预约日期，因此改期会改变记录所属日期。
- 新接口：`GET /v1/appointments/:id/reschedule?scope=mine|clinic` 获取预约版本和变更历史；`POST` 同一路径提交 `scope/date/slot/reason/version/requestKey`。预约列表现在返回 `version`，原状态变更接口也要求提交该版本；确认、取消、到店和完成接诊均会推进版本，旧页面不能误处理改期后的预约。
- 本阶段未运行测试或编译，使用验证由用户安排。

### 护理与复查待办筛选

- 诊所工作台新增“查看逾期事项”“待反馈护理”“待处理反馈”三个快捷入口，医生和管理员可用。入口会清空原筛选条件并切换对应进度；前台仍只接收预约事项，不能查看护理、反馈或复查。
- 待办支持事项类型（预约与接诊、护理、复查、需关注）和进度组合筛选：当前待办、全部跟踪、逾期、今日到期、待反馈、待处理反馈、待编写、复查待预约、暂缓跟进。可继续按姓名或事项关键词、医生、事项日期范围缩小结果，筛选即时生效；重置恢复默认当前待办。
- 默认“当前待办”沿用原来需要员工执行的事项：预约处理、护理草稿、已提交但未处理的反馈、逾期未反馈护理、已到再次联系时间的逾期未预约复查。工作台待办总数仍统计这些实际待办，不因增加跟踪记录而膨胀。
- “待反馈”为已发送且未提交反馈的护理任务，包含未到期和逾期；“待处理反馈”只表示已提交待诊所处理，护理草稿单列“待编写”。需关注依据现有反馈标记，不新增临床判断或自动分析。
- “复查待预约”包含未到建议日期及已逾期但无有效预约的安排。“暂缓跟进”为已逾期但内部再次联系日期在未来的安排，能在跟踪和逾期视图中查到，仍不进入默认当前待办；日期到达后恢复待办。未到期或暂缓的复查仅提供查看安排和电话联系，不直接给出“现在跟进”任务。
- “逾期”包括已过日期未到店的已预约、已过反馈日期未提交的护理、已过建议日期未预约的复查（含暂缓跟进）。当天不算逾期；已提交待处理反馈不会因旧反馈日期而被重复算作逾期，目前没有设置反馈处理时限。
- 日期范围按预约日期、护理反馈日期、复查建议日期筛选，含起止两天，任一端可不填。复查内部再次联系日期不替代建议日期作为筛选基准。草稿反馈日期是未发送时的暂定值。“今日到期”同样使用这些事项日期（北京时间）。开始晚于结束显示提示。
- 标签数量按当前其他筛选条件计算，类型数量保留当前进度，进度数量保留当前类型；标签可能重叠，不能相加。刷新保留筛选，返回工作台可再次进入；账号或端切换清空条件。全部跟踪仍为当前未完成事项，不包含已处理护理、已预约或完成的复查历史。
- “全部跟踪”是该待办队列的跟踪范围，不是所有预约的副本；未来尚未到店的已确认预约仍在“预约管理”查看。
- 原 `GET /v1/worklist` 的 `items` 增加未到期的待反馈护理、待预约及暂缓跟进复查，并新增 `state/actionable/overdue/filterDate/deferred` 元数据。`counts.all` 及分类数只计 `actionable` 项，`counts.tracked` 表示全部跟踪项数。服务端继续按角色限定返回数据，筛选在小程序内完成。
- 本阶段未运行测试或编译，使用验证由用户安排。


### 科普分类与文章

- 管理员维护分类名称、标题、摘要、纯文本正文与一个可选关联服务；可创建草稿、编辑保存、发布、下架和重新发布。正文最多 20000 字，保留段落换行；发布要求已保存非空正文。原首页示例只迁移标题与服务关联，正文由诊所提供及审核，默认不对患者展示。
- 患者首页显示最新三篇已发布文章；科普列表可按分类、关键词组合查询标题/摘要/正文，每页 20 条并可加载更多。详情展示正文与关联服务预约入口，停用服务保留名称但不提供预约；跳转前重新校验文章发布状态与服务，预约继续使用现有成员、医生及号源流程。
- 草稿和下架文章仅管理员可读，医生及前台不能管理内容。患者不能通过旧详情地址读取已下架文章；已在设备上显示过的内容需重新加载才反映下架。切换账号、端或重新登录清空内容数据，过期请求不会覆盖新筛选或新身份。
- 文章和分类保存在 SQLite，重启不覆盖维护内容；修改与发布下架使用版本校验，冲突时返回列表重新加载后编辑。已发布文章保存后立即更新患者可见内容，需暂停展示时先下架。操作记录保留操作人、前后内容及时间，尚无审计查询界面。
- 接口：`GET /v1/articles?q=&category=&page=1`、`GET /v1/articles/:id`；管理员使用 `GET/POST /v1/admin/articles`、`GET/PUT /v1/admin/articles/:id`、`POST /v1/admin/articles/:id/status`（`version/status`，发布为 `published`、下架为 `offline`）；分类使用 `POST /v1/admin/article-categories` 与 `PUT /v1/admin/article-categories/:id`，管理列表同时返回分类及数量。
- 本阶段不含富文本/图片/视频、收藏、分享、阅读历史、原创署名、独立审核队列或阅读/转化统计。可运行 `node server/tests/articles.cjs`、`node server/tests/articles-page.cjs` 完成隔离接口与页面逻辑检查；均已通过，资料配置回归也通过。微信编译和实际界面验收由用户安排。

### 诊所、医生与服务资料配置

- 管理员入口：“诊所工作台 → 诊所、医生与服务资料”。可维护诊所名称、联系电话、地址、营业时间和简介；新增医生及项目，编辑资料和启停。患者从首页“诊所与医生资料”查看诊所与团队、联系诊所，或从医生和项目资料开始预约。
- 医生资料包括姓名、职称、执业信息、擅长、简介与可预约项目；项目包括名称、说明、预约准备与参考时长（1–480 分钟）。正式资料由管理员补充，系统不会生成或核验执业资质；初始介绍和联系方式留空，不编造资料。
- 医生可预约范围全部不选表示提供所有启用项目（包含以后新增项目），也可明确限定项目。预约界面按项目显示医生，服务端同时校验指定医生及不限医生分配。排班、员工医生授权、护理模板、检索和统计改用数据库中的动态名单。
- 停用资料保留已有预约及历史记录，仍可完成已有预约接诊。停用医生不接受新预约、复查预约、改期、员工医生授权或新开放号源；停用项目或调整医生项目范围后，相应的新预约、复查和改期会拦截。恢复启用会沿用原排班开放状态，请先核实已有排班。医生资料启停与员工账号权限独立，离职员工需在员工名单另行停用。
- 已保存的医生和项目名称沿用旧系统的预约/身份关联键，暂不支持改名；可修改其他资料，名称更换需新增资料并停用旧资料。停用医生及项目名称仍可用于历史检索、统计和护理模板维护。服务参考时长仅展示，号源仍按半小时，不自动占用多个时段；营业时间也不自动生成或关闭排班。
- 资料保存在 SQLite，启动只补入初始资料，不覆盖管理员维护内容或恢复停用资料。保存使用版本校验并记录操作人、前后资料及时间；冲突时返回管理列表重新加载后编辑。当前没有头像上传、执业资料审核、统一审计查询或删除资料功能。
- 接口：`GET /v1/catalog` 返回启用资料及历史筛选名称；管理员使用 `GET /v1/admin/catalog`、`PUT /v1/admin/catalog/clinic`、`POST /v1/admin/catalog/doctors|services`、`PUT /v1/admin/catalog/doctors|services/:id` 维护。号源接口可传 `service` 参数，按医生服务范围及启用状态筛选。
